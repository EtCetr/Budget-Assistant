# DECISIONS.md
Журнал архитектурных и технологических решений проекта «Семейный финансовый ассистент»
Цель: Фиксация ключевых выборов, причин и отвергнутых альтернатив для предотвращения регрессии и контекста для AI-ассистентов.
Последнее обновление: Этап 12

## 🏗 АРХИТЕКТУРА И ПРИНЦИПЫ
| Решение | Обоснование | Отвергнутые альтернативы |
| --- | --- | --- |
| Offline-First | Все действия сначала пишутся в локальную БД (sync_status='pending'). Синхронизация асинхронная в фоне. | Online-first, прямые HTTP-запросы из UI |
| Clean Architecture + Feature-First | Слои data/domain/presentation изолированы. Фичи живут в features/. UI не знает о БД. | MVC, MVVM без разделения, Layer-First |
| Иммутабельность моделей | DTO и сущности создаются через freezed. Изменение состояния только через копирование. | Mutable классы, setState внутри моделей |

## 🛠 ТЕХНОЛОГИЧЕСКИЙ СТЕК
| Технология | Роль | Почему выбрано | Почему отвергнуто другое |
| --- | --- | --- | --- |
| Flutter + Dart | Фреймворк | Нативная производительность, единая кодовая база, Hot Reload | React Native, Native Kotlin |
| Riverpod | State Management | Compile-time безопасность, независимость от BuildContext, async из коробки | Provider, BLoC, GetX |
| Drift | Локальная БД | Типобезопасный SQL, JOIN/оконные функции, миграции, watch() | sqflite, Hive/Isar |
| Supabase | Backend | PostgreSQL, RLS, real-time, бесплатный tier | Firebase, Custom backend |
| GoRouter | Навигация | Декларативный синтаксис, deep links, guard'ы | auto_route, Navigator 2.0 |
| WorkManager | Фон | Нативный Android API, энергоэффективность, constraints | flutter_background_service, Isolates |

## 💰 ДАННЫЕ И ТОЧНОСТЬ ВЫЧИСЛЕНИЙ
| Правило | Обоснование | Нарушение ведёт к |
| --- | --- | --- |
| Суммы в IntColumn (копейки) | IEEE 754 double накапливает ошибку. Финансы требуют точности. | Расхождение балансов, неверная аналитика |
| Деление на 100 ТОЛЬКО в UI | Бизнес-логика и БД работают с целыми числами. | Утечка неточности в расчёты |
| Даты в UTC | Конвертация в локальное время при выборке. | Слом аналитики вне UTC |
| Обязательные индексы | date, category_id, account_id, sync_status, expires_at. | Full-scan, лаги при >5k записей |
| Инвестиции изолированы от P&L и шифруются E2E | Пополнение брокерского счёта = transfer; сервер не видит состав портфеля. | Искажение аналитики, утечка данных портфеля |

## 🔒 БЕЗОПАСНОСТЬ И СИНХРОНИЗАЦИЯ
| Правило | Обоснование | Нарушение ведёт к |
| --- | --- | --- |
| E2E шифрование AES-256-GCM | Чувствительные поля шифруются на клиенте ДО отправки. Ключ в flutter_secure_storage. | Утечка данных при компрометации бэкенда |
| Никаких секретов в коде | Ключи только в SecureStorage / env. | Декомпиляция APK → полный доступ |
| Идемпотентный upsert | Конфликты через updated_at. Автоматическая перезапись запрещена. | Потеря транзакций, дубликаты |
| Таблица sync_conflicts | Неразрешимые конфликты требуют ручного резолва. | Тихая порча данных |

## 🎨 UI И ПРОЦЕСС РАЗРАБОТКИ
| Правило | Обоснование |
| --- | --- |
| DTO/UiModel как буфер | Запрещён прямой доступ к Drift-сущностям из виджетов. |

## Обновления решений (Этап 8 + микро-коммиты, 2026-09-11)
- «Исключить из учёта (сторно)» удалено из продукта. `AuditStatus.ignored` сохранён в enum для совместимости.
- Крупные траты: `transactions.is_large_expense` (Bool, default false), long-press пометка, фильтр «Без крупных».
- Фильтр суммы в логе транзакций сравнивает `ABS(amount)`.
- Монотонные часы для sync_locked: `SystemClock.elapsedRealtime()` через MethodChannel `budget_assistant/clock`.
- Схема БД: schemaVersion = 4 на тот момент (далее 5–9 по этапам).

## Обновления решений (Этап 12 — Цели накопления)
| Решение | Обоснование |
| --- | --- |
| `auto_reminder_enabled` default TRUE (БД и форма) | Решение владельца; закрывает противоречие ТЗ 6.3.16.14.9a (FALSE) и 6.3.17.5 (TRUE). |
| `savings_goals.completed_at` (nullable) | Одноразовое конфетти + дата «Завершена …» в архиве. Отклонение от ТОМ 2 §14.1, обосновано ТЗ 6.3.16.6 и 6.3.47. |
| Пополнение цели — всегда `type='expense'` | 'transfer' для виртуальных целей (6.3.16.7) невозможен без счёта-приёмника; P&L уже исключает цели через `savings_goal_id IS NULL`. |
| `current_amount` — строго read-only | Обновляется только через UpdateSavingsGoalProgressUseCase; защита от рассинхрона с историей транзакций. |
| Мультивалютная агрегация целей — в Dart через цепочку курсов Этапа 10 | Единый фолбэк «последний известный курс»; SQL-JOIN из ТЗ не даёт этого поведения. |
| Экспорт аналитики: XLSX + CSV + PNG + **PDF** | Требование владельца (формат банковских сводок). В режиме hidden экспорт полностью заблокирован. |
| Эмодзи цели хранится внутри `name` | Отдельной колонки в ТОМ 2 нет; форма склеивает эмодзи и название при сохранении. |
| `savings_goals` не в SyncTableSpec до Этапа 25 | Прецедент cashback_matrix/dashboard_widgets: локальные данные с `sync_status='pending'`, облачная синхронизация после создания таблиц в Supabase. |
