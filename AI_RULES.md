## 🔴 КРИТИЧЕСКИЕ ПРАВИЛА (нарушение = баги в коде)

### 1. ВСЕГДА проверяй содержимое файлов ПЕРЕД генерацией кода
❌ НЕ делай: «Предполагаю, что у тебя есть файл X, вот код для него…»
✅ ДЕЛАЙ: сначала попроси показать содержимое:
   «Пришли содержимое файла X» или «Выполни: Get-Content path/to/file.dart»
Почему: без реального содержимого ты не знаешь сигнатур, имён полей и структуры.
Генерация вслепую = 5–10 итераций исправлений.

### 2. Проверяй версии пакетов в pubspec.yaml ПЕРЕД использованием API
❌ Logger('Name')            // сигнатура logger 1.x
✅ Logger()                 // logger 2.x: позиционного имени НЕТ
Частые ловушки:
- logger 2.x vs 1.x — разные сигнатуры конструктора и метода e()
- DropdownButtonFormField: value deprecated → использовать initialValue
- build_runner: флаг --delete-conflicting-outputs УДАЛЁН в новых версиях
- Riverpod 3.x: StateNotifier/StateNotifierProvider УДАЛЕНЫ → Notifier/NotifierProvider
- Freezed 3.x: классы должны быть abstract

### 3. Получай реальные сигнатуры конструкторов ПЕРЕД вызовом
Команда проверки:
Select-String -Path lib/.../file.dart -Pattern 'class ClassName\(' -Context 10
Пример: конструктор TransactionsRepositoryImpl({required AppDatabase db, required Logger logger})
→ вызывать ТОЛЬКО с именованными: TransactionsRepositoryImpl(db: db, logger: logger)

### 4. Проверяй наличие файлов ПЕРЕД импортом
Команда проверки:
Get-ChildItem lib -Recurse -Filter *.dart | Where-Object { $_.Name -like '*имя*' }
Если файла нет — не импортируй его: используй существующие провайдеры/репозитории
или спроси пользователя, где лежит нужный файл.

## 🟠 ВАЖНЫЕ ПРАВИЛА (нарушение = потеря времени)

### 5. Проверяй кодировку файлов (UTF-8 BOM ломает кодогенерацию)
Симптомы BOM (байты EF BB BF в начале файла):
- freezed/drift_dev падают с «Variables must be declared using…» / «Illegal character»
- «Missing concrete implementations» после генерации
- PowerShell-замены текста не применяются
Проверка:
$bytes = [System.IO.File]::ReadAllBytes('file.dart')
if ($bytes[0] -eq 0xEF -and $bytes[1] -eq 0xBB -and $bytes[2] -eq 0xBF) { 'BOM!' }
Лечение:
$new = $bytes[3..($bytes.Length-1)]; [System.IO.File]::WriteAllBytes('file.dart', $new)

### 6. Freezed-классы — ВСЕГДА с ключевым словом abstract
✅ @freezed abstract class X with _$X { const factory X({...}) = _X; }
После правок entity-файлов перегенерируй принудительно:
dart run build_runner clean
Get-ChildItem -Path lib -Recurse -Filter *.freezed.dart | Remove-Item -Force
dart run build_runner build

### 7. Читай содержимое enum-файлов ПЕРЕД использованием констант
Пример ошибки: SyncStatus.error не существует, реальные значения: pending, synced, conflict.
Команда: Get-Content lib/core/enums/transaction_enums.dart

### 8. Для русской локали intl добавляй инициализацию в main()
import 'package:intl/date_symbol_data_local.dart';
import 'package:intl/intl.dart';
await initializeDateFormatting();
Intl.defaultLocale = 'ru';
Без этого DateFormat.MMMEd('ru') падает с LocaleDataException прямо в UseCase.

### 9. После git commit --amend уже запушенного коммита — объясняй force-push
git push --force-with-lease origin main
Объясняй причину: amend переписал SHA, remote отклоняет non-fast-forward.
--force-with-lease безопаснее --force (не затрёт чужие коммиты).

### 10. Проверяй дубли роутов ПЕРЕД добавлением в app_router.dart
(Select-String -Path lib/core/router/app_router.dart -Pattern "path: '/имя'").Count
Дубль name/path роняет приложение на старте:
«duplication fullpaths for name …» (assert в go_router).

## 🟡 ПРАВИЛА КОММУНИКАЦИИ (нарушение = фрустрация пользователя)

### 11. Не говори «вставь строку» без точного якоря
✅ «В файле X найди функцию Y. Сразу после открывающей скобки { добавь: …»
✅ Ещё лучше: «Найди блок кода Z и замени его целиком на: …»

### 12. Давай готовые файлы ЦЕЛИКОМ, а не патчи
Пользователь-новичок теряется в точечных правках. Формат:
«Вот полный файл X (замени содержимое целиком): [весь код]»
Патчи допустимы только для очень больших файлов и только с точными якорями «найти/заменить».

### 13. Признавай свои ошибки сразу, не перекладывай на пользователя
❌ «У тебя неправильная сигнатура, исправь»
✅ «Моя ошибка: в logger 2.x сигнатура другая. Вот исправленный код: …»

### 14. Спрашивай предпочтения ПЕРЕД генерацией спорной логики
Пример: фильтр суммы по модулю vs по знаку; семантика сегмента «Семейные».
Сначала вопрос с вариантами, потом код выбранного варианта.

### 15. Объясняй ожидаемое поведение фич ДО теста пользователем
Если действие не даёт видимого эффекта на текущем этапе (например, «Засекретить»
видно только в CalendarScreen на Этапе 14) — скажи об этом заранее:
что запишется в БД, что будет видно сейчас, что появится позже и как отменить.

## 🟢 АРХИТЕКТУРНЫЕ ПРАВИЛА (из DECISIONS.md, нарушать запрещено)

16. Деньги — ТОЛЬКО IntColumn (копейки). double запрещён везде, кроме форматирования в UI.
17. Даты — ТОЛЬКО UTC; локальное время через datetime(date, 'localtime') при выборке.
18. Offline-First: любая запись создаётся с sync_status = 'pending'; sync асинхронный (WorkManager).
19. E2E: чувствительные поля шифруются AES-256-GCM ДО отправки в Supabase; ключи только в SecureStorage.
20. Clean Architecture: UI не знает о БД; цепочка UI → Provider → UseCase → Repository → Drift.
    Фильтры — ТОЛЬКО в SQL (WHERE), никогда в UI-слое. Хардкод строк/лимитов в UI запрещён.
    Все операции в try/catch с логированием. Один этап = один коммит.
